Functional RequirementsThe functional requirements define the main operations and services that the MIND Architecture Web Application must provide to support users, administrators, members, content management, bookings, purchases, and accessibility.1. User Registration and AuthenticationThe system shall allow new users to create an account.The system shall allow registered users to log in securely using their email and password.The system shall allow users to log out securely.The system shall validate user credentials before granting access.The system shall display error messages for invalid login attempts.The system shall maintain user sessions after successful login.2. User Roles and Access ControlThe system shall support different user roles such as normal user, premium member, admin, and owner.The system shall restrict admin-only pages and features from normal users.The system shall allow only authorized users to access content management features.The system shall enforce membership restrictions for premium-only content.3. Profile and Membership ManagementThe system shall allow users to view their profile information.The system shall allow users to update selected profile details.The system shall store membership status for each user.The system shall display whether a user is on a free or premium membership plan.The system shall prevent users who are already premium members from purchasing the same premium upgrade again.4. Public Website ContentThe system shall provide public pages such as Home, About, Programs, Resources, Gallery, Testimonials, Insights, Membership, Contact, and Consultation.The system shall display only published content on public pages.The system shall hide unpublished content from public users.5. Events ManagementThe system shall display available events to users.The system shall show event title, date, venue, description, and pricing.The system shall support event categories.The system shall support member pricing for selected events.The system shall support members-only events.The system shall allow users to view event details.The system shall allow users to book events.The system shall create an event booking record after successful booking.The system shall reduce available seats after confirmed event bookings.The system shall display event bookings in the user dashboard.The system shall allow admins to add, edit, hide, and delete events.6. Books and ResourcesThe system shall display available books and resources to users.The system shall allow users to search books by title.The system shall allow users to filter books by category.The system shall display book details including title, author, price, member price, and description.The system shall support members-only books.The system shall allow users to add books to the cart.The system shall allow users to update or remove cart items.The system shall allow admins to add, edit, hide, and delete books.7. Cart and CheckoutThe system shall maintain a shopping cart for authenticated users.The system shall calculate totals based on selected quantities and prices.The system shall apply member pricing where applicable.The system shall create pending orders before payment processing.The system shall support Stripe developer test checkout for book purchases.The system shall verify payment success before marking an order as paid.The system shall clear the cart after successful payment.The system shall automatically cancel pending book orders after one hour if payment is not completed.The system shall display order history in the dashboard.8. Membership FeaturesThe system shall display membership plans and comparison information.The system shall allow users to select the premium membership plan.The system shall support Stripe developer test checkout for premium membership.The system shall update a user’s membership status to premium after successful payment verification.The system shall apply premium-only access rules after membership activation.The system shall apply member pricing to books and events for premium users.9. Blog and InsightsThe system shall display blog posts and insights articles.The system shall allow users to open and read blog posts.The system shall support members-only blog posts where applicable.The system shall allow admins to add, edit, hide, and delete blog posts.10. Consultation and ContactThe system shall provide a consultation page with booking-related information.The system shall allow users to submit consultation requests.The system shall store consultation requests in the database.The system shall allow visitors to send contact messages.The system shall store contact messages in the backend.The system shall allow admins to review contact messages.11. DashboardThe system shall provide a user dashboard for authenticated users.The system shall display user profile details in the dashboard.The system shall display event bookings in the dashboard.The system shall display book orders in the dashboard.The system shall display consultations in the dashboard.The system shall display membership status in the dashboard.The system shall show order status such as pending, paid, cancelled, or delivered.12. Order TrackingThe system shall allow tracking information to be recorded for physical orders.The system shall store carrier, tracking number, and tracking URL for orders.The system shall generate an Australia Post tracking link where applicable.The system shall allow users to view tracking links from the dashboard.The system shall allow admins to update order tracking details.13. Admin PanelThe system shall provide an admin panel for authorized users.The system shall allow admins to manage events, books, blogs, users, and orders.The system shall allow admins to change membership status of users.The system shall allow admins to review orders and update order tracking.The system shall allow admins to review and manage published content.The system shall restrict admin features from unauthorized users.14. Payment IntegrationThe system shall support Stripe integration in developer test mode for book purchases.The system shall support Stripe integration in developer test mode for premium membership.The system shall support Stripe integration in developer test mode for event booking.The system shall verify payment status before updating related records.The system shall store payment-related references for completed transactions.The system shall be ready to switch from Stripe test mode to live mode once client business details are provided.15. Accessibility FeaturesThe system shall provide a high-contrast accessibility mode.The system shall provide read aloud or hover-read support.The system shall allow users to access accessibility controls from the navigation bar.The system shall keep accessibility controls available across the website.16. Chat WidgetThe system shall display a chat widget on the website.The system shall load the chat widget in minimized form by default.The system shall allow the user to open the chat widget manually.The system shall use the updated Tawk widget configuration provided by the client.17. Content Management and Final Client ContentThe system shall support replacement of placeholder/demo content with final client-provided content.The system shall allow content updates for events, books, testimonials, blogs, membership, consultation, and contact details.The system shall support final review and refinement before deployment.18. Deployment ReadinessThe system shall be prepared for deployment after testing and content finalization.The system shall support frontend and backend integration in a deployment-ready state.The system shall support final testing before being moved to production use.
